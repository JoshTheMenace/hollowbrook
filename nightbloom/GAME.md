# GAME.md — Nightbloom, the game contract

The town of 宵坂 (Yoizaka) is generated by the city-scale pipeline
(city-plan.json is the town's contract). THIS file is the game's contract on
top of it — every system below names its gate.

## The loop

One in-game day ≈ 8 real minutes, three phases:

1. **DAY (~5 min)** — third-person exploration. The player (CharForge ronin,
   later unlockable cast) walks the town, talks to NPCs at their posts, runs
   quests along flood-fill-verified routes, spends gold in market shops
   (upgrades persist per save). Music: adaptive loop at intensity 0.1-0.4.
2. **DUSK (~30 s)** — scripted transition. DayNight fades day → dusk → night,
   lanterns take over, the shrine bell knocks once by itself, NPCs walk home
   (despawn at doors). The yagura drum becomes interactable: striking it (or
   waiting out dusk) starts the night.
3. **NIGHT (~2.5 min cap)** — spirit-blossoms bloom over the festival ground.
   The survivors Run engine (charforge, balance-gated) drives a horde fight
   inside the arena rect the plan reserves (x 29..53, z -3..15). Night ends at
   the survival timer or player defeat; defeat costs half the night's gold,
   never progress. Music: same loop, intensity driven 0.5 → 1.0 by the Run's
   live pressure (enemy count + player hp).

Meta: gold, weapon/passive unlocks (survivors choices persist as a run-start
loadout), day counter, quest log — versioned localStorage save.

## Cast placement (day posts)

- elder — shrine hall front (quest giver: the town's history, night warnings)
- mika — canal lane west footbridge (fetch/delivery quests)
- fox — shrine-rise mound, flees to festival ground at dusk (chase quest)
- shopkeepers — implied by lit interiors + door chimes; not modeled as bodies
  in v1 (doors + voices), so the no-people base town degrades gracefully.

## Systems and their gates

| System | Source | Gate |
|---|---|---|
| Town | city pipeline | check-city.mjs (seams, floodfill, corridors, budgets) |
| Combat | @forge survivors Run (bounds-injectable) | charforge simulate-run.mjs ALL PASS |
| Night arena siting | arena rect clear of colliders | check-city district contract + a game gate: floodfill the arena rect at night-spawn ring |
| Audio | @forge soundforge runtime (setIntensity) | charforge check-audio.mjs ALL PASS |
| Day/night | src/game/daynight.js (3 poles + traveling practicals pool) | screenshot pair day/night per district in review passes |
| Characters | @forge characters via Actor | charforge check-character/anatomy/weapons gates |
| Quests | data-driven (src/game/quests.js), nodes = plan waypoints | every quest route flood-fill reachable; headless quest-sim walks each quest start→end |
| Juice/SFX | @forge engine juice bus + soundforge SFX bank | juice lint (no unwired event) + audio gates |

## Hard rules

- The base town must keep passing check-city with the game code absent —
  game layers are additive modules (src/game/), never edits to districts/kit.
- Every gameplay event is wired in the juice table or it fails the lint.
- Audio dies with its scene (dispose on phase/scene exit).
- No system ships on "looks right" — each has a headless gate or a
  screenshot-pair review named above.
